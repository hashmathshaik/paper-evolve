# Paper Evolve UI review — November 14, 2026

Reviewed the interface view by view and made the following changes. Kept the single search entry point and the user's Qwen pause.

| Area | Finding | Change and verification |
| --- | --- | --- |
| Landscape | A global Evolution button could choose an unselected paper. Paper sorting did not affect area cards. | Removed the global action, placed Evolution actions on individual paper rows, and hid paper sorting for grouped views. Verified row selection opens the exact named paper. |
| Landscape | Category cards used opaque labels and changing colors; counts lacked context. | Display Uncategorized research, stable category colors, paper/topic counts and clear View topics/View papers actions. Hide redundant root breadcrumbs and correct singular labels. |
| Browse | Twenty long paper rows separated users from pagination. | Added paging above and below results, preserving the current page through Back navigation. Hide paging and sorting when unnecessary for a single result. |
| Evolution | Fit could stop at a zoom level that still overflowed the panel. Small movements could become drags when zoomed out. | Removed the former 35% floor, retained readable initial zoom, and use screen-pixel drag thresholds. Verified a 365 × 261 timeline fits within a 546 × 316 panel. |
| Evolution | Trace-path mode lacked clear success/no-path feedback. A filtered-out selection could leave the map focused on an invisible paper. | Added persistent origin, valid-path and missing-path messages; select a visible paper when filtering removes the previous selection. Verified CacheBlend → KVLink and a disconnected reverse selection. |
| Paper reader | A paper opened from the library was described as having no relationships before those relationships were inspected. | Use a neutral invitation to inspect evolution. Graph-origin reader connections now follow active graph filters and show evidence labels. |
| Text and formulas | Some abstracts displayed prose formatting commands, raw formulas and unlinked URLs. | Added display-only prose cleanup, safe HTTP(S) links and bundled KaTeX 0.19.1 with local fonts. Keep original data unchanged. Verified five rendered formulas in a real abstract, including on a 390px phone viewport. |
| Search and navigation | Empty Enter and browser history were inconsistent. | Empty Enter opens the collection. Header navigation uses history so Back restores the previous view and list page. Retained one visible search field. |
| Asset delivery | A browser cache served the earlier zoom implementation after edits. | Added stable content-based UI versions to local and static builds. Tests check that real edits refresh all references and repeated builds do not churn versions. |

## Closure verification

All findings in the table above are implemented. The follow-up fix pass also addressed these remaining failure cases:

- A failed evolution request now produces a centered load-error state with Retry timeline, Read abstract and Back to papers. It is distinct from genuinely missing prepared data, hides irrelevant zoom/path controls and never displays an old graph as the requested paper.
- Failed shard promises are removed from the cache, allowing Retry to recover.
- Navigating elsewhere or choosing a newer paper invalidates an older asynchronous evolution task. Controlled out-of-order completion checks verify that an old result cannot repaint the new selection.
- Example timelines are matched by paper identity, including arXiv versions, instead of a short title prefix. Different OpenReview IDs and different explicit source URLs cannot be conflated.
- Collection-loading errors have an explicit Retry collection action.

Live recovery check: temporarily withheld the first evolution shard in the source and static build, observed the failure state for Probabilistic FastText for Multi-Sense Word Embeddings, verified its abstract was still available, restored both original files, then successfully retried the same timeline. No test data files were left missing. Qwen stayed paused throughout.
